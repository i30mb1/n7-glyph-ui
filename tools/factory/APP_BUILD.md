# Building one n7 Glyph app from its spec

You build a complete Android app for the Glyph Matrix on the back of the Nothing Phone (3) from a finished design spec.
The owner publishes these apps on Google Play and other people will check after them that EVERYTHING works, so "it compiles" is not the bar:
every state in the spec must exist, be reachable, and be covered by a test that would fail if it broke.

## Read first, completely
1. Your app's spec (path given in your task).
2. `PLATFORM_FACTS.md` and `KIT_SPEC.md` next to this file.
3. The toy kit source: `D:\AndroidProject\n7-glyph-ui\n7-glyph-ui\src\main\kotlin\n7\glyph\ui\toy` and `...\matrix`, and the library README.
4. The template you start from: `D:\AndroidProject\n7-glyph-ui\template` (every file).
5. The house style in production: `D:\AndroidProject\glyph-pet` (`MainActivity.kt`, strings, `app/src/main/play/`, `docs/privacy.html`, tests).
6. Look rules: `D:\AndroidProject\n7-glyph-ui\store\ds\README.md`. Store kit usage: `STORE_SPEC.md` next to this file and `D:\AndroidProject\n7-glyph-ui\store\render.py --help`.

## Rules
- Create the project with the generator, never by hand:
  `python D:\AndroidProject\n7-glyph-ui\tools\new_app.py --dir <project dir> --package <package> --name "<title>" --repo <dir name>`
- Gradle ONLY through `python D:\AndroidProject\n7-glyph-ui\tools\gw.py <project dir> <args>` (10-minute tool timeout). Other agents build at the same time; the wrapper queues.
- Do not edit anything under `D:\AndroidProject\n7-glyph-ui` (library, template, store kit, tools). If the kit lacks something, work around it inside your app
  and say so in your report. Do not touch other apps. Do not commit, tag or push; you may run `git init` in your new project.
- No new permissions, no network, no extra dependencies.
- Write multi-line scripts to a file with the Write tool and run the file; shell heredocs with backticks or backslashes break here.

## What the template already gives you (checked on the real phone and on Gradle)
- `toy/GlyphToyService.kt`: the SDK plumbing. Leave it byte-for-byte as generated. It already guarantees: one `onRelease` per `onLongPress`
  (also when the button-up event is lost, on always-on and on unbind); a fresh engine per bind; sensors only while live; `still()` for always-on;
  a clean handover when the player switches between two toys of the same app; debug logs under the tag `GlyphToy`.
- Right under the app name the screen shows ONE line that says what the app is (string `tagline`, English and Russian, 40 characters
  at most so it stays on one line, `N7Type.Body` in `N7Colors.InkMuted`, 12 dp under the headline). The owner asked for this on 2026-11-15;
  an app without it is not done.
- `MainActivity.kt`: the house screen with the setup card, `ToyStage` (the live toy on screen with the on-screen Glyph button), the "How it works" card,
  a slot for your cards, `MoreFromN7`, the signature. Keep this order and look; replace the demo content.
- Release build with R8 (`optimization { enable = true }`, keep rules in `app/src/main/keepRules/rules.keep`), signing, Play Publisher: do not change.
- `StoreFramesTest` writing `app/build/store/frames.json` and `frames.txt`; `store/store.json`; the launcher icon and toy preview drawables are
  generated by the store kit from `store.json` AFTER the unit tests have written the frames (`render.py <dir> --only drawables --only icon`).
- The demo (`game/DemoEngine.kt`, `toy/DemoToyService.kt`, its tests, strings, store frames) is example code: replace all of it, leave no trace.
- The engine API guarantees to rely on: every engine call happens on the main thread; `ToyStage` and the service each create their own engine,
  so anything they must share (records, settings) goes through storage, read by the engine when it needs it.

## Architecture (as in the template)
- `game/`: pure Kotlin. One `ToyEngine` per toy plus shared rules. No Android imports. Time only through `frame(dtMs)`. Randomness through a
  `kotlin.random.Random` passed into the constructor. Saved data through a small interface the engine receives (implemented over SharedPreferences
  in the app, over a map in tests), so the toy service and the app screen share records.
- `toy/`: `GlyphToyService.kt` from the template unchanged, and one tiny service per toy that returns its engine.
- `MainActivity.kt`: the house screen. The live `ToyStage` runs the same engine; if the app has several toys, a row of secondary buttons or
  cards switches which toy the stage shows. Records and settings in `N7Card`s. Every string in `values/` (English) and `values-ru/` (Russian, short, «ты»).
- Manifest: one `<service>` per toy with its own name, summary and preview drawable; `aod_support` only where the spec says so.

## Tests (JUnit 4, `app/src/test`)
- Invariants for every engine: over long random runs with random motion and button events, every frame has 625 values within 0..4095,
  lights only visible cells, and never throws.
- The spec's "Engine test plan", case by case.
- A scenario test per toy that plays the spec's "First ten seconds" and a full round, asserting the states it passes through.
- `still()` leaves the state unchanged.
- `StoreFramesTest`: renders the frames the store shots and the icon need with the REAL engines and writes `app/build/store/frames.json`.
- Also write `app/build/store/frames.txt`: an ASCII dump of those frames (`#` > 60% brightness, `+` > 25%, `.` lit, space off). Look at it yourself:
  if a picture is not recognisable there, it will not be recognisable on the phone. Fix the drawing, not the dump.

## Store and listing (inside the project)
- `store/store.json` per `STORE_SPEC.md`: icon (one red element), one preview drawable per toy, feature graphic, 5 shots as the spec lists them.
  A shot with layout `screen` needs a real screenshot at `store/screens/<name>.png`, which is taken later on an emulator; until then render only what does not need it
  (`--only icon`, `--only drawables`, `--only feature`) so the launcher icon and toy previews in `res/drawable` are the real ones.
- `app/src/main/play/`: `listings/en-US` and `ru-RU` (`title.txt` max 30 chars, `short-description.txt` max 80, `full-description.txt` max 4000, glyph-pet's structure and tone),
  `release-notes/en-US/default.txt` and `ru-RU/default.txt`, `contact-email.txt`, `contact-website.txt` (https://github.com/i30mb1/<repo>), `default-language.txt`.
  Promise only what the app does. Say plainly that it needs a Nothing Phone (3).
- `docs/privacy.html`: accurate for this app (which sensors, what is stored on the device, nothing collected).
